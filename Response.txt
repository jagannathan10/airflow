Important Context First:
You are correct that Control-M is a commercial, licensed enterprise job scheduler with specific UI-driven features, while Airflow is an open-source workflow orchestration platform built for programmatic authoring, scheduling, and monitoring of workflows.
We can compare them in terms of functionality, but they differ fundamentally in design philosophy:

Control-M is job-centric with a GUI-first configuration approach.

Airflow is DAG (Directed Acyclic Graph) and code-centric, treating workflows as pipelines with dependencies.

Comparing them directly can be misleading because Airflow is not just a “job scheduler” but a platform to define, run, and monitor complex workflows as code, with extensibility and integration capabilities that differ from traditional enterprise schedulers.

Answers to Your Airflow Questions:
1. Is Job re-run supported in Airflow?
Yes, Airflow supports re-running tasks and entire DAG runs. You can clear the state of tasks to trigger re-execution.

2. If Yes. Will it support re-run after scheduled job Failed / Success?
Yes. From the UI, you can clear failed or successful tasks (or entire DAG runs) to re-run them.

3. If re-run is supported job retrigger will initiate from the point of failure job or from the starting job.
By default, re-running a DAG (by clearing task states) will restart from the tasks you cleared. However, because Airflow respects task dependencies, you can choose to re-run from a specific task (and downstream tasks) or from the start.

4. Does Airflow support job hold and release.
Yes. In the Airflow UI, you can pause a DAG, which prevents any new scheduled runs from being triggered. You can also mark tasks as “failed” or “success” manually to release blockers.

5. How about Adhoc cyclic job which gets triggered every 1 hr during the business hours
You can define a DAG with a schedule interval of @hourly or 0 * * * * and use a TimeSensor or branching logic to skip runs outside business hours, or use a custom schedule with a CRON expression that limits to business hours (e.g., 0 9-17 * * 1-5 for 9 AM–5 PM on weekdays).

6. Understand Airflow doesn’t have any UI which is currently available in ControlM. In this case how can all the job be monitored and controlled.
This is not accurate — Airflow has a rich web UI for monitoring and controlling DAGs and tasks. It includes:

DAG/task status views (tree, graph, calendar, Gantt chart)

Log viewing

Task retry, clear, mark success/failed

Variable/connection management

SLA monitoring

It may lack some enterprise job-scheduling-specific UI features, but it is fully capable of monitoring and controlling workflows.

7. Does Airflow support to modify the job parameters and trigger the job with new parameter.
Yes, via Airflow’s “Conf” parameter when triggering a DAG manually. You can pass a JSON configuration. Within a DAG, you can use {{ dag_run.conf }} to access these parameters. This allows runtime overrides.

8. Does Airflow support Job Statistics which currently ControlM does
Airflow provides metrics and logging, and you can integrate with tools like StatsD, Prometheus, or Grafana for statistics. The UI shows duration, success/failure rates, and you can export data for analytics. Out-of-the-box detailed historical reporting may require customization compared to Control-M.

9. Does Airflow support Country based Calendar to manage the holidays
Not natively, but you can implement it via:

Using a custom Holiday calendar with Python’s workalendar library in your DAG logic.

Creating a sensor or branching operator to check holidays and skip execution.

Storing holiday dates in a table or file and referencing them.

10. Does Airflow supports ordering the jobs
Yes — tasks are ordered within a DAG using set_upstream/set_downstream or bitshift operators (>>, <<). For ordering across DAGs, you can use ExternalTaskSensor or trigger DAGs via API.

11. Managing the independent jobs through cron is difficult to handle and writing cron jobs for 140+ jobs would be difficult to complete within the short timeline.
Exactly — this is where Airflow shines. Instead of managing 140+ independent cron jobs, you can:

Define all workflows in code (Python DAGs).

Centralize logging, monitoring, and alerting.

Handle dependencies, failure recovery, and parallelism in a unified system.

Use a single scheduler to manage all schedules, reducing operational overhead.

Final Note:
While Airflow may not have every built-in enterprise feature that Control-M offers (like out-of-the-box holiday calendars or certain UI wizards), it makes up for it with flexibility, scalability, and code-driven automation, which is preferred in modern data engineering stacks. Migrating from cron to Airflow for 140+ jobs is a significant improvement in maintainability and visibility.
